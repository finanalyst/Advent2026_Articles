Ringing in the changes

Using Raku++ to create website functionality

Gifts this year§

Two talented Raku community members - Andrey Shitov and Tokuhiro Matsuno - have developed two new Raku compilers using Generative AI tools. Andrey's Raku++ compiles to C++ and Tahiro-san's mutsui compiles to Rust. Since there are now transpilers from C++ and Rust to WASM (a language that works inside a browser), both compiler stacks offer a way to write Website functionality in Raku. I consider both Raku++ and mutsui to be amazing gifts to the Raku community this year, so thank you to both Andrey and Tahiro-san.

Since I far prefer writing programs in Raku than in Javascript, I was excited to try one of the above to move functionality in the new documentation website to Raku.

The new website deployment is still being tested, but both Raku++ and mutsui can be invoked in the website by clicking on the Raku icon on the right-hand side.

For the purposes of this article, I can only use one of these projects, and there is a lot of documentation to read. In addition, I have a bit more familiarity with C++ than Rust, but that should not matter, but it slightly tilted my decision to use Raku++ for this test.

Greetings in other languages§

If you take a look at the new Raku documentation website, you will see a drop-down to select the UX language. The goal is to have Raku documentation in multiple languages, and for the UI language to be independent of the content language (current multi-lingual sites change both the navigation and content together which is a pain if you just want to check on some item in another language, but have to work out how to get to it in the other language).

Essentially all user-facing text is held in HTML spans with a key, and the web page is shipped with a map from from the language / key to the text to be used.

What I want to explore is how much of the functionality currently implemented in Javascript can be implemented in Raku, and whether there is a performance hit. Articles about WASM indicate that Javascript will be faster for this sort of functionality and that other language implementations in WASM will be faster for calculation heavy functionality, so this particular example should not have any performance benefit.

Main components§

The Javascript program has been split into four components between script tags:

  • a dictionary which contains the three greetings and language name keyed by language and token
  • code to generate the drop-down selection based on the languages in the dictionary
  • code to replace the text of spans with the selected language
  • code that runs when the DOM has settled, including a search to gather into an Array all the DOM elements containing spans that have tokens that need replacing.

Moving into Raku?§

The first step is to move the dictionary to Raku (again this is nowhere near optimal given that the dictionary is simply a native Javascript object).

Apart from the hash definition, the Raku program is trivial. Lets assume this is the content of a text file called r-funtions.raku:

After installing the raku++ compiler as described in Install raku++ , we compile this to a Javascript file called rFunctions.js as follows 

    raku++ -o rFunctions.js --js --standalone r-functions.raku
Code3.

Notes:

  • The raku++ version must be > 5.11.0.
  • The rFunctions.js file needs to be served to the webpage, so the source used below is from a github repo via a cdn (directly sourcing from github runs into a NoSniff error).
  • The options for raku++ are given in more detail in the project's dpcumentation, however
  • -o is the output (compiled) file name;
  • --js indicates the compilation target;
  • --standalone indicates only one file is to be created; and
  • the final option is the input file name

In order to link the Raku to the webpage, we add two scripts into the document head section, namely

Populating DOM elements from within Raku§

In order to introspect the DOM of the HTML file, and to modify it, raku++ has the use js pragma. The pragma creates a new JS object, which can then be treated as the gloabal This.

We add the following function to our r-functions.raku file: 

use js;
sub changeLang( $new-lang, $tag-class) is export {
    my $doc = JS.document;
    my @targets = $doc.querySelectorAll( $tag-class );
    for @targets {
        my $token = .getAttribute('data-UIToken');
        .innerHTML = %h{ $new-lang}{$token};
    }
}
Code6.

Then we replace the snippet in Code5 with 

ruiselector = document.getElementById('rElucid8_ui-switch-contents');
makeUISelector( defLang, ruiselector );
changeLang( defLang, '.r-Elucid8-ui');
rSetUI( rtoken_spans, defLang );
ruiselector.addEventListener('change', (event) => {
    newLang = event.target.value;
    changeLang( newLang, '.r-Elucid8-ui');
});
